# MODULE 14: DJANGO API AUTHENTICATION & SECURITY | TOKEN AUTH | JWT | CORS | PAGINATION

## CLASS OVERVIEW
A public API with no authentication is a security risk. This class secures the toriloshop API with Token
authentication and JWT, adds CORS headers so browser-based clients can call the API safely, adds
pagination so large lists do not overwhelm clients, and adds filtering so users can search without loading all
data. By the end, toriloshop has a production-grade, secure, and well-structured API. 


## 1. TOKEN AUTHENTICATION
DRF Token Authentication issues each user a unique token string. The client sends this token in the
Authorization HTTP header on every request. The server checks the token and identifies the user — no
session or cookie required. This makes it ideal for mobile apps and third-party API consumers.

## 2. JWT AUTHENTICATION WITH SIMPLEJWT
JWT (JSON Web Tokens) is a more modern authentication standard. Instead of storing tokens in the
database, JWT encodes user information directly into a signed token string. It uses two tokens: a short-lived
access token (15 minutes) and a longer-lived refresh token (1 day or more) used to get a new access
token without requiring the user to log in again.

## 3. CORS — CROSS-ORIGIN RESOURCE SHARING
CORS is a browser security policy that blocks JavaScript running on one domain from making requests to a
different domain. When a React frontend at localhost:3000 tries to call your Django API at
localhost:8000, the browser blocks it unless Django explicitly allows it. The django-cors-headers
package adds the correct response headers to allow this.

**Install cors headers package**
-> python -m pip install django-cors-headers

-> Then add to installed apps

-> Add the corsheader middleware — must be ABOVE CommonMiddleware

```py
-> add this in settinggs.py
# Allow all origins during development — restrict in production
CORS_ALLOW_ALL_ORIGINS = True

# In production, specify exactly which origins are allowed
# CORS_ALLOWED_ORIGINS = [
# 'https://yourfrontend.com',
# 'https://www.yourfrontend.com',
# ]
```

## KEY TAKEAWAYS FROM CLASS
• Token auth: user POSTs credentials, gets a token, sends Token in Authorization header on every
request.
• JWT: access token (short-lived, sent with requests) + refresh token (long-lived, used to get new access
tokens).
• JWT uses 'Bearer' prefix in the Authorization header. Token auth uses 'Token' prefix.
• CORS blocks browsers from calling APIs on different domains — django-cors-headers adds the
required response headers.
• Pagination splits results into pages — the response includes count, next, previous, and results.
• Search, filter, and ordering backends let clients query data efficiently using URL query parameters.
• Always protect write operations (POST, PUT, DELETE) with IsAuthenticated or a custom permission
class.
